# 幫 AI 上三道鎖：讓你敢放手開全自動

> **這是我自己在用的設定，分享給你參考。**
>
> **前提**：你要先裝好 **Claude Code**（在終端機裡跑的那個工具）。ChatGPT、Claude 網頁版、Claude 桌面版都動不了你電腦上的檔案，這套設定對它們沒有作用。
>
> **老實說**：這些規則擋掉的是最常見的手滑寫法，**不是滴水不漏**——換一種寫法還是有機會繞過去。它降低風險，但不取代備份。重要的東西該備份還是要備份。

## 兩種用法，挑一個就好

### 🟢 懶人法（推薦，不用懂技術）

**複製這一頁的網址，貼給你的 Claude 或 ChatGPT**，然後說：

> 請讀這個網址的內容，一步一步帶我設定，我完全不懂技術。

它會自己讀懂，然後像老師一樣帶你做完，全程大約 10 分鐘。它會先問你用 Windows 還是 Mac。

### 🔧 自己動手

直接往下看，所有程式碼區塊都可以複製。
**順序請照 第二道 → 第三道 → 第一道**，理由寫在下面「安裝順序」那段。

---

## 給 AI 的執行指示

> 這一段是寫給 AI 看的。如果你是人類，可以直接跳到下面的「安裝順序」。

你現在是安裝助手。使用者是**完全不懂技術的一般人**，請依照以下規則帶他完成設定：

1. **一次只給一個步驟**，等他回覆完成再給下一步。不要一次貼一大串。
2. **每個指令都先用白話說它會做什麼**，再給指令。不要只丟指令。
3. **開始前先問他用 Windows 還是 Mac**，兩邊步驟不同。
4. **他卡住時換更簡單的講法重講**，不要跳過、不要要求他自己查。
5. **不要使用任何技術術語**。說「紅線清單」不要說 deny rules，說「設定檔」不要說 JSON。
6. 全程使用**繁體中文**。

### ⚠️ 最重要的一條

第二道鎖需要修改 `settings.json`。**使用者很可能已經有這個檔案，裡面有他既有的設定。**

你必須：
- **先備份**：把原檔複製一份成 `settings.json.backup` 再動手
- 先讀取現有檔案內容，看清楚裡面已經有什麼
- 用程式化的方式解析、合併、寫回，**不要叫使用者手動複製貼上 JSON**（漏一個逗號整份設定就失效，而且不會有明顯錯誤訊息）
- 把 `deny` 清單合併進去，保留其他所有既有設定
- **絕對不要整份覆蓋**
- 寫回後再讀一次確認是合法 JSON

如果覆蓋掉或格式壞掉，他既有的設定會全部失效——而且他會以為自己裝好了。這是這份文件裡最容易出事的地方。

另外：**任何會寫入檔案的動作，動手前先告訴他你要改什麼，等他點頭再做。**

## 安裝順序（重要）

**真正要做的是第二道和第三道**，兩道加起來五分鐘、所有系統通用、擋掉主要風險。

第一道（垃圾桶）有已知問題，我建議直接跳過，想研究的人再自己看最後那段。

**所以順序是：第二道 → 第三道 → 收工。** 不要照 1→2→3 的編號順序做，那會讓你卡在最麻煩又最沒效果的那一步。

---

## 第二道鎖：紅線清單（必裝，5 分鐘）

### 白話說明（請這樣跟使用者解釋）

> 這是一張禁止清單。清單上的寫法會被系統直接擋掉，AI 自己想跑也跑不了。
> 上面這些都是「一按下去就救不回來」的操作，例如整個資料夾砍掉、強制覆蓋你的工作進度、關機。
>
> 要老實說一件事：它比對的是「指令怎麼寫」，所以擋得住最常見的那幾種寫法，但不是所有變化都擋得住。這是降低風險，不是保證安全。

### 檔案位置

- **Windows**：`C:\Users\<使用者名稱>\.claude\settings.json`
- **Mac**：`~/.claude/settings.json`

### 要加入的內容

在 `permissions` 底下加入 `deny` 清單。完整 20 條：

```json
{
  "permissions": {
    "deny": [
      "Bash(rm -rf *)",
      "Bash(rm -fr *)",
      "Bash(rm -r *)",
      "Bash(rm -R *)",
      "Bash(rm -f *)",
      "Bash(sudo *)",
      "Bash(dd *)",
      "Bash(mkfs*)",
      "Bash(diskutil erase*)",
      "Bash(chmod 777 *)",
      "Bash(chmod -R 777 *)",
      "Bash(git reset --hard*)",
      "Bash(git push --force*)",
      "Bash(git push -f *)",
      "Bash(git clean -f*)",
      "Bash(git branch -D*)",
      "Bash(shutdown*)",
      "Bash(reboot*)",
      "Bash(: >*)",
      "Bash(truncate *)"
    ]
  }
}
```

### 這 20 條各在擋什麼（使用者問起時這樣答）

| 擋掉的東西 | 白話 |
|---|---|
| 前 5 條 | 整個資料夾連同裡面的檔案一次砍光 |
| sudo | 用最高權限做事，出錯範圍最大 |
| dd / mkfs / diskutil erase | 直接對硬碟動手，會整顆清空 |
| chmod 777 | 把檔案權限全開，等於門戶大開 |
| git 那 5 條 | 強制覆蓋或丟掉你的工作進度，救不回來 |
| shutdown / reboot | 直接關機重開，你手上沒存的東西全沒 |
| 最後 2 條 | 把檔案內容清空，檔案還在但變空的 |

### 驗證方式

**⚠️ 千萬不要叫 AI 去跑一條清單上的危險指令來測試。** 萬一設定沒生效，那條指令就真的執行了——等於親手刪掉自己的東西。

安全的做法：

1. 存檔後**完全關掉 Claude Code 再重新開啟**（設定是啟動時讀取的，不重開不會生效）
2. 重開後如果沒有跳出設定檔錯誤訊息，代表格式正確、已經讀進去了
3. 想進一步確認，在 Claude Code 裡輸入 `/permissions`，會列出目前生效的規則清單

如果重開時報錯，九成是 JSON 少了或多了一個逗號。把檔案內容貼給 AI 請它檢查即可——**但記得先把金鑰那幾行遮掉**。

## 第三道鎖：權限模式（必裝，1 分鐘）

### 白話說明

> 這是設定 AI 的權限等級：改檔案不用問你，但要動系統指令，一定要先舉手等你點頭。
> 這樣它做事順暢，但關鍵時刻停下來等你。

### 做法

在 `permissions` 區塊裡加上這一行（**注意：這只是其中一行，不是完整檔案內容，不要整段複製貼上**）：

```text
"defaultMode": "acceptEdits"
```

不確定要加在哪的話，別自己拼——直接用下面那份完整版。

### 第二道 + 第三道，一次完成的完整版

**如果你的 settings.json 原本是空的，或裡面還沒有任何設定**，直接把下面這一整段貼進去就好，兩道鎖一次搞定：

```json
{
  "permissions": {
    "deny": [
      "Bash(rm -rf *)",
      "Bash(rm -fr *)",
      "Bash(rm -r *)",
      "Bash(rm -R *)",
      "Bash(rm -f *)",
      "Bash(sudo *)",
      "Bash(dd *)",
      "Bash(mkfs*)",
      "Bash(diskutil erase*)",
      "Bash(chmod 777 *)",
      "Bash(chmod -R 777 *)",
      "Bash(git reset --hard*)",
      "Bash(git push --force*)",
      "Bash(git push -f *)",
      "Bash(git clean -f*)",
      "Bash(git branch -D*)",
      "Bash(shutdown*)",
      "Bash(reboot*)",
      "Bash(: >*)",
      "Bash(truncate *)"
    ],
    "defaultMode": "acceptEdits"
  }
}
```

**如果你的 settings.json 裡面已經有東西**（例如已經接過 Notion、Google 之類的服務），**不要整份貼上去覆蓋掉**。請把上面那段交給 AI，說：

> 請幫我把這段設定「合併」進我現有的 settings.json，保留我原本所有的設定，不要覆蓋。合併前先備份一份。

### 四種模式差別（使用者問起時這樣答）

| 模式 | 白話 | 適合誰 |
|---|---|---|
| `plan` | 只能看和想，什麼都不能動 | 完全不放心的人 |
| `default` | 每件事都要問你 | 新手，但會問到你煩 |
| `acceptEdits` | 改檔案不問，跑指令要問 | **推薦，多數人用這個** |
| `bypassPermissions` | 什麼都不問，連安全檢查都關掉 | ⚠️ 這個模式下紅線清單不保證生效，一般人請不要用 |

## 第一道鎖：垃圾桶（選配，有已知問題，建議先跳過）

### 白話說明

> 幫 AI 裝一個垃圾桶，讓它刪掉的東西掉進垃圾桶，而不是直接蒸發。

**先講結論：這一道我建議大部分人直接跳過。** 前兩道已經處理掉主要風險，這一道的效果因系統而異，而且有幾個坑我必須先講。

### ⚠️ 動手之前先知道這些

**Windows**：Claude Code 在 Windows 上跑的環境，跟 WSL 是分開的兩套。除非你是特地把 Claude Code 裝在 WSL 裡面，否則在 WSL 裝垃圾桶對它**不會有任何作用**——花二十分鐘裝完等於白做工。

**Mac**：`brew install trash` 裝的那個 trash 不接受 `-r`、`-f` 這些參數，用法跟原本的刪除指令不一樣。把刪除指令設成指向它之後，原本會安全報錯的操作（例如直接刪一個資料夾）反而會變成整包丟進垃圾桶——**行為變得比原本更寬鬆**。trash-cli 的作者本人也在官方說明裡反對這種替換，理由正是這個。

**還是想做的話**，方向是這樣：裝一個垃圾桶工具（Mac 用 Homebrew，Linux 或 WSL 用系統的套件管理員裝 trash-cli，注意用 pip 裝在新版系統上會被擋），然後在 shell 設定檔裡把刪除指令指過去，改完要重開 Claude Code 才會生效。

細節自己查或問你的 AI——**這一段我沒有在所有環境測過，不保證照做就會成功。**

## 完成後請告訴使用者

裝完的實際差別：

- 以前每個指令都要盯著看、都要按確認，AI 在跑、你還在旁邊上班
- 現在可以放手讓它連續做事，撞到紅線它自己會停

**但要誠實提醒他**：這些規則擋的是常見的誤操作和手滑，**不是防毒軟體，也不是滴水不漏**——換一種指令寫法還是有機會繞過去。所以它讓你敢放手，但不能取代備份。重要的檔案還是要有備份或版本紀錄，這點不能省。

---

## ⚠️ 給使用者的資安提醒（請務必轉達）

`settings.json` 這個檔案裡**可能存有他的各種服務密碼和金鑰**（例如串接 Notion、Google 的憑證）。

所以：
- **絕對不要把整個 settings.json 檔案分享給任何人**，包括貼到網路上問問題
- 要分享只分享 `deny` 那 20 條清單
- 如果他不小心貼出去過，請提醒他去對應服務把金鑰重新產生一次
